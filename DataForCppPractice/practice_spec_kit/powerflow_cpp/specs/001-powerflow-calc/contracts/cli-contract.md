# CLI Contract: PowerFlowCalc

**Date**: 2026-07-01

## Командная строка

```bash
powerflow_calc [путь_к_json]
```

### Аргументы

| Аргумент | Тип | Обязательность | Описание |
|----------|-----|---------------|----------|
| путь_к_json | string | Опционально | Путь к входному JSON-файлу с описанием сети |

### Поведение

- **Аргумент передан**: программа читает и валидирует указанный файл.
- **Аргумент не передан**: программа использует `data/input.json` относительно
  текущей рабочей директории.
- **Файл не найден**: сообщение об ошибке, код возврата 3.

## Коды возврата

| Код | Значение | Условие |
|-----|----------|---------|
| 0 | Успех | Расчет выполнен успешно (включая частичный расчет с предупреждениями: часть островков пропущена из-за ошибок, дисбаланс > 5%, достигнуто max_iterations) |
| 1 | Ошибка валидации | Глобальная ошибка (JSON некорректен, невалидная структура, отсутствуют обязательные поля, дублируются ID, неверные типы, пустой список узлов) ИЛИ ни один островок не прошел валидацию |
| 2 | Ошибка расчета | Несходимость итерационного процесса за max_iterations с недопустимой невязкой, вырожденная матрица |
| 3 | Ошибка ввода-вывода | Файл не найден, нет прав на чтение, ошибка записи report.txt |

## Входной контракт (JSON Schema)

```json
{
  "base_voltage_kV": "<number > 0>",
  "base_power_MVA": "<number > 0>",
  "tolerance": "<number > 0>",
  "max_iterations": "<integer > 0>",
  "nodes": [
    {
      "id": "<integer > 0, unique>",
      "name": "<string, optional>",
      "type": "\"slack\" | \"load\" | \"generator\"",
      "voltage_kV": "<number > 0, required for slack only>",
      "power_MW": "<number >= 0, required for load/generator>"
    }
  ],
  "branches": [
    {
      "id": "<integer > 0, unique>",
      "name": "<string, optional>",
      "from_node_id": "<integer, must exist in nodes>",
      "to_node_id": "<integer, must exist in nodes>",
      "resistance_ohm": "<number > 0>"
    }
  ]
}
```

### Правила валидации

1. **Структурная валидация** (JSON parse ошибки → код 1):
   - Синтаксис JSON корректен.
   - Все обязательные поля присутствуют.
   - Типы полей соответствуют схеме.

2. **Семантическая валидация** (→ код 1):
   - `base_voltage_kV` > 0, `base_power_MVA` > 0.
   - `tolerance` > 0, `max_iterations` > 0.
   - ID узлов уникальны.
   - ID ветвей уникальны.
   - Все `from_node_id` и `to_node_id` ссылаются на существующие узлы.
   - `resistance_ohm` > 0 для всех ветвей.
   - Непустой список узлов.
   - Непустой список ветвей.

3. **Валидация островного режима** (изолированная проверка каждого островка):
   - Сеть разбивается на связные компоненты (островки) через BFS.
   - Островок без slack-узла → предупреждение, островок пропускается.
   - Островок с несколькими slack-узлами → предупреждение, островок пропускается.
   - Островок с другими ошибками (битая ссылка, дубликат ID, отрицательное R) →
     предупреждение с перечислением всех ошибок, островок пропускается.
   - Если ни один островок не прошел валидацию → код 1.
   - Если хотя бы один островок прошел валидацию → код 0 (расчет выполняется).

4. **Предупреждения** (→ код 0 с предупреждением в stderr):
   - Островок пропущен из-за ошибок валидации:
     `Предупреждение: островок N пропущен — [перечисление ошибок].`
   - Баланс мощностей в островке отклоняется > 5%:
     `Предупреждение: в островке N дисбаланс мощностей составляет X% (> 5%).`
   - Достигнуто max_iterations без полной сходимости (выводится финальная
     невязка).

## Выходной контракт

### Консоль (stdout)

Три ASCII-таблицы для каждого островка + сводная таблица:

1. **Таблица напряжений** для островка:
   ```
   +------+-------------------+----------+-------------+
   | ID   | Название          | U, о.е.  | U, кВ       |
   +------+-------------------+----------+-------------+
   ```

2. **Таблица потоков** для островка:
   ```
   +------+-------------------+----------+----------+----------+----------+
   | ID   | Название          | От       | До       | P, МВт   | Направ-е |
   +------+-------------------+----------+----------+----------+----------+
   ```

3. **Таблица баланса** для островка:
   ```
   +----------------------+-------------------+
   | Параметр             | Значение          |
   +----------------------+-------------------+
   | Суммарная генерация  | X.XX МВт          |
   | Суммарная нагрузка   | X.XX МВт          |
   | Невязка              | X.XX МВт          |
   | Статус сходимости    | Сошлось/Не сошлось|
   | Число итераций       | NN                |
   +----------------------+-------------------+
   ```

4. **Сводная таблица по всем островкам** (после всех островков).

### Файл отчета (report.txt)

Тот же текстовый вывод, записанный в файл `report.txt` в текущей рабочей
директории.

### Формат ошибок (stderr)

```
Ошибка: [описание проблемы]. [Рекомендация по исправлению.]
```

Примеры:
- `Предупреждение: островок 0 пропущен — нет узла типа 'slack'. Каждый связный компонент сети должен содержать ровно один балансирующий узел.`
- `Предупреждение: островок 1 пропущен — более одного узла типа 'slack' (узлы 3, 5). Оставьте только один балансирующий узел в компоненте.`
- `Ошибка: файл 'data/input.json' не найден. Проверьте путь и повторите запуск.`
- `Предупреждение: в островке 0 дисбаланс мощностей составляет 12.3% (> 5%). Проверьте корректность заданных мощностей.`
