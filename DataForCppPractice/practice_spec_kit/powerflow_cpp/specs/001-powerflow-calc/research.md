**Date**: 2026-07-01

## 1. Математическая модель: знаки матрицы проводимостей

### Decision

Принята следующая система знаков для матрицы проводимостей Y:
- **Диагональные элементы**: Y(i,i) = −Σ(g_ij) — сумма проводимостей всех
  ветвей, подключенных к узлу i, со знаком **минус**.
- **Внедиагональные элементы**: Y(i,j) = +g_ij для связанных узлов, 0 для
  несвязанных.

Итерационная формула: U_i_new = (I_i − Σ_{j≠i} Y(i,j) × U_j) / Y(i,i)

### Rationale

Данная система знаков вытекает из записи законов Кирхгофа в форме узловых
напряжений для сети постоянного тока: сумма токов, втекающих в узел i,
Σ_j g_ij × (U_j − U_i) = I_i. После приведения к матричной форме получаем
Y×U = I с указанными знаками. Эта форма удобна для итерационного выражения
U_i через остальные переменные.

### Alternatives

- Вариант с положительной диагональю Y(i,i) = +Σ(g_ij) и отрицательными
  внедиагональными элементами Y(i,j) = −g_ij (классическая форма Y_bus).
  Отвергнут, так как требует изменения знака в итерационной формуле и
  усложняет проверку матрицы.

## 2. Метод решения: простая итерация

### Decision

Основной метод — простая итерация (метод Якоби) для системы Y×U = I.
Альтернативный метод (прямое решение через Eigen, метод Гаусса) остается
опциональным для P3.

### Rationale

- Простая итерация естественно ложится на нелинейную задачу I = P/U, где
  вектор токов зависит от напряжений.
- Для сетей DC сходимость гарантирована при диагональном преобладании матрицы
  Y, что выполняется для физических сетей.
- Метод прост в реализации и отладке.
- Прямое решение через Eigen (partialPivLu, colPivHouseholderQr) доступно как
  fallback для проверки результатов.

### Alternatives

- Метод Гаусса-Зейделя (последовательное обновление U_i на каждой итерации).
  Сходится быстрее, но не дает преимущества для малых сетей (≤20 узлов).
- Прямое решение СЛАУ через Eigen::PartialPivLU. Требует линеаризации I=P/U
  (фиксация токов на текущей итерации), что эквивалентно простой итерации.

## 3. Алгоритм выделения островков

### Decision

Поиск связных компонент графа через BFS (поиск в ширину) от каждого
непосещенного узла. Для каждого островка проверяется наличие ровно одного
slack-узла.

### Rationale

- BFS прост в реализации, гарантирует нахождение всех компонент связности.
- Сложность O(V + E) для разреженного графа, при ≤20 узлах — пренебрежимо мала.
- Позволяет собрать узлы и ветви, относящиеся к каждому островку, за один
  проход.

### Alternatives

- DFS — эквивалентен по сложности, BFS выбран как более наглядный.
- Union-Find (DSU) — не дает преимуществ при малом размере графа.

## 4. Выбор тестового фреймворка

### Decision

Google Test (gtest) через CMake FetchContent.

### Rationale

- Широко распространен, хорошая документация.
- Встроенная поддержка CTest.
- Поддержка параметризованных тестов (для перебора тестовых JSON-файлов).
- FetchContent позволяет не требовать предустановленной библиотеки.

### Alternatives

- Catch2 — также header-only, более легковесный, но с менее удобной
  интеграцией с CTest для параметризации.
- doctest — минималистичный, но ограниченная экосистема.

## 5. Работа с Eigen

### Decision

Eigen::MatrixXd для плотной матрицы проводимостей. Для решения СЛАУ
(при прямом методе) — Eigen::PartialPivLU<Eigen::MatrixXd> для матриц
размера до 20×20.

### Rationale

- Header-only, не требует компиляции.
- Оптимизирован для плотных матриц малого размера.
- PartialPivLU достаточен для невырожденных матриц проводимостей.
- При 20 узлах плотная матрица 20×20 = 400 элементов, double = 3200 байт —
  хранение не является проблемой.

### Alternatives

- Eigen::SparseMatrix — избыточен для ≤20 узлов.
- Armadillo — тяжелее по зависимостям.
- Ручная реализация Гаусса — избыточно при наличии Eigen.
